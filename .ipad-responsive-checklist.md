# iPad Responsive Checklist

Target breakpoints: **768px (portrait)** and **1194px (landscape)**, covers iPad Mini/Air/9th-gen (768/810/820) through iPad Pro 12.9" (1024 portrait / 1366 landscape — treat 1194 as the practical mid-large landscape target since Tailwind's `lg:1024` already kicks in before it).

Tailwind config needs a custom breakpoint added before starting (if not already present):
```js
// tailwind.config.js — theme.screens
screens: {
  ...defaultTheme.screens, // keep sm/md/lg/xl/2xl
  'ipad': '768px',
  'ipad-lg': '1194px',
}
```

## Per-page workflow (one page per loop iteration)

1. Pick the next `todo` route (top to bottom).
2. Screenshot BEFORE at both viewports (768×1024 portrait, 1194×834 landscape) using Playwright.
3. Identify concrete problems: overflow-x, cramped/overlapping text, touch targets <44px, wasted whitespace, desktop-only multi-column squeezed too narrow, mobile-only single-column wasting landscape width, sticky/fixed elements colliding.
4. Fix via Tailwind classes using `ipad:`/`ipad-lg:` (or existing `md:`/`lg:`) — layout/JSX changes allowed if they genuinely improve tablet UX (e.g., 1-col → 2-col on landscape, repositioning sticky panels, adjusting nav).
5. Screenshot AFTER at both viewports, compare against BEFORE — confirm the specific problems from step 3 are resolved and nothing else regressed (check the same page's mobile `sm` and desktop `xl` screenshots too, to catch breakpoint regressions).
6. Update this table's Status to `done` with a 1-line Notes summary of what changed.
7. Commit: `git add` only the touched files (+ this checklist) → commit message `fix(responsive): improve iPad layout for <route>`.
8. Stop for this iteration. Next loop iteration picks the next `todo` row.
